# Arc Llama 1.0 Readiness Audit

Audit date: 2026-09-13  
Branch: `release/1.0-prep`  
Scope: readiness work other than the public RC stabilization period and final 1.0 publication.

This is a local working note. It is intentionally not committed.

## Results

### First-run and diagnostics

- PASS — `.venv/bin/arc-llama --version` reports `0.9.0.dev0`.
- PASS — `arc-llama --help`, `run --help`, and `serve --help` complete.
- PASS — `arc-llama gpus` detects the host Intel Arc Pro B60 at `0000:06:00.0`.
- PASS — `arc-llama doctor` completes and reports the SYCL runtime, llama-server,
  Level Zero, ReBAR, and the configured B60.
- ACTION — Doctor warns that the user is not in the `render` and `video` groups.
  This needs a documented first-run remediation or a deliberate supported-host
  requirement before 1.0.
- ACTION — Doctor reports the expected approximately 20-second SYCL JIT cold
  start unless the llama.cpp binary is built with the B60 AOT target. Document
  this prominently or provide the recommended binary/build path.

### Runtime and routing

- PASS — ArcLlama service starts on the B60/SYCL host.
- PASS — Proxy-derived per-model recipes are loaded from the host config.
- PASS — Real cold-start and switch: LFM2.5 loaded, then ArcLlama evicted it,
  started Ornith, and returned a successful completion. Health then reported
  exactly one loaded model.
- PASS — The single-resident VRAM-admission regression test passes.
- PASS — Ruff reports no issues.
- PASS — Buddy review set: 88 relevant router, eviction, fast-path, server,
  streaming, and preflight tests passed; mypy was clean for `router.py` in that
  review environment.

### Automated validation status

- BLOCKED — Full `pytest tests/` now passes through the autotune and router
  load-error coverage (21% / 949 tests) after fixing two executor stalls in
  missing/tiny-model paths, but still stalls in
  `test_failed_persist_rolls_back_the_edit_and_reports_failure` while entering
  its FastAPI `TestClient`. The remaining startup/test-harness stall needs a
  separate diagnosis before release.
- BLOCKED — `.venv/bin/mypy --check-untyped-defs src` exits with mypy 2.3.1's
  internal-error message rather than a type result. This is a tooling/version
  issue until reproduced in clean CI.
- PASS — `uv build --out-dir /tmp/arc-llama-dist` produced a wheel and sdist;
  the wheel installed into an isolated target, imported successfully, and
  included the bundled static UI and generated plugin assets.
- PASS — `git diff --check` is clean and the branch working tree was clean before
  this uncommitted audit note was added.

### Hardware matrix

- RECORDED — Linux x86-64, Intel Arc Pro B60/Battlemage, xe driver, SYCL,
  24 GB reported VRAM, Level Zero available, real model inference and switching
  verified.
- NOT RUN — Linux Vulkan on this host.
- NOT RUN — Windows x86-64.
- NOT RUN — Intel Arc Alchemist consumer hardware.
- NOT RUN — Lunar Lake hardware.
- NOT RUN — clean-install runs from a fresh Python environment and empty
  configuration/state directories.

## Remaining actionable work before 1.0 scope is ready

1. Reproduce and fix or explain the remaining full-suite startup/test-harness
   hang in `test_failed_persist_rolls_back_the_edit_and_reports_failure`.
2. Resolve the mypy 2.3.1 internal error in a clean supported environment.
3. Keep the successful wheel/sdist and bare-wheel install checks in CI.
4. Add or document the `render`/`video` group remediation and the B60 SYCL JIT
   expectation.
5. Complete the Linux Vulkan and Windows/Alchemist hardware matrix, or clearly
   mark unsupported combinations before the release candidate.
6. Exercise `arc-llama run` from an empty configuration with a local GGUF and a
   Hugging Face GGUF specification.

## Deliberately excluded

The public 0.9 RC stabilization period and final 1.0 versioning/publication
steps are tracked separately in `docs/1.0-plan.md` and are not part of this
local audit.

## Follow-up verification: 2026-09-18

The original results above are historical. At baseline commit `81c33f4`, the
full Python suite passed outside the restricted agent sandbox: 936 passed,
13 skipped in 18.94 seconds. The reported persistence-test stall reproduced
inside that sandbox, including with an empty FastAPI app, but the isolated
rollback test passed outside it in 0.41 seconds. See `docs/testing.md` for
reproduction guidance and the limits of this diagnosis.

The current mypy run no longer crashes internally. It found three ordinary
type errors in the UI-layout response; an explicit response-dictionary type
resolved them. Ruff and mypy then passed. Wheel and source-distribution builds
and a bare-wheel import/static-asset check also passed. These results do not
replace the still-required GPU/backend and clean-machine hardware matrix.
